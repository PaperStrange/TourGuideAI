# 候选 12 相机提示缺失的实际几何复现

候选 12 原生浏览器在 16 次已收敛的同向绕转后仍未显示提示。原始失败报告 SHA256 `e625fdcb2bd81daee2c47bbdf7d7b1b466feeeefe354816b2b0db918f1ba4cc8`，包 SHA256 `e86aa1c715fb76cd111feae41a0383ee34005aefd64fe5c48eba7615676e5733`；保留 6 项通过、2 项失败，后续语言与清除检查未执行。

本目录保存一次获准的 CPU 几何复现。脚本验证相机、遮挡器和提示检测器与源码提交 `06a2c496da689b5c18797b2f77ef1f03cb2857ab` 的字节完全相同，读取该冻结包及原始报告的实际驻留单元与级别，使用真实 OrbitControls、相机模块、BVH 和来源阻挡判定。监听包装仅记录实际求解器返回值，不替代几何或求解结果；不加载图像、不创建浏览器，也不证明外观质量。

16 步最终相机位置与原生报告的最大距离差为 `3.5307186881363175e-14` m，提示回调始终为空。第 9、10 步的同步调用明确记录：

1. `beginCameraInput` 先采用已经安全的可见视点；视角没有实际进展，此时 `active=false`。
2. 新的 `+0.08` 弧度绕转随后进入受约束方向，`active=true`，并经原有恢复过程收敛。
3. 旧检测器在第一步没有待评估绕转时遇到 `!active`，清空此前连续受限次数，因此无法累计到三次。

这些同步调用发生在浏览器首次输入后采样之前，是原先仅使用最终姿态的纯检测器测试未覆盖的集成路径。已有 UI 回调及可见性条件未发现对应错误。

修正仅在内部采用安全视点的原有 `emitChange` 同步期间跳过提示观察，并用 `finally` 恢复观察。求解器调用、控制器操作、相机值、碰撞、人物限制和帧调度全部保持原样。新增实际驻留几何回归验证所有 16 步位置、目标、期望位置及矩阵保持在 `1e-9` 范围内；第三次稳定受限尝试（索引 9）只发出一次 true，主动俯仰随后清除。10 项针对性检查通过，独立工程复核通过。当前原始复现报告始终保留修正前的空回调，不能作为修正后的浏览器通过证据。

三个 gzip 文件保留实际执行脚本、完整求解器调用/姿态报告及原始标准输出；压缩及解压身份见 `binding.json`。原始浏览器失败报告与驱动由 QA 独立归档。新候选还需验证提示显示、双语、清除路径及原有相机行为。
