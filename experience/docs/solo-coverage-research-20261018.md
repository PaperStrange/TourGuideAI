# Solo exploration coverage · 18 October 2026

Research proposal and shared-palette module for the next implementation decision. Source inspected: `245a1f364aa3b04e270d2d6ee402e31ec3b9d3ce`. World-map integration and browser validation are tracked separately. All production-cost rankings below are engineering estimates, not supplier quotations or measured development time.

## Recommended method

Use the existing global map as the continuous exploration surface, with one maintained visual style and explicit area discovery. Add reviewed area packs when a place needs richer identity or grounded interactions. Licensed photographs can provide optional visual evidence. Reserve scanned scenes for selected destinations where owned capture material and a concrete experience justify their preparation.

For the immediate solo pilot, the useful action is **move the map toward an interesting spatial feature, explore that area, choose an actual returned place, and retain the chosen place and view for a later visit**. A river edge, park boundary or dense group of streets supplies a visual reason to explore. The person chooses what matters to them. Enjoyment and emotional attachment remain outcomes to test with people.

## Current implementation and limits

- `src/home/world-map.js` already uses MapLibre and `https://tiles.openfreemap.org/styles/liberty`. It keeps a map instance, supports pan/zoom/orbit, and draws dashed lines between selected stops. The actual downloaded style renders `building-3d` with `render_height`/`render_min_height` from the provider. Local views use zoom 16.3/pitch 56; country views use zoom 4/pitch 0.
- `src/discovery/provider.js` already accepts any valid center coordinate, queries up to 30 English Wikipedia articles within 1,200 m, preserves article IDs and source coordinates, and applies bounded category and distance checks. `routes.js` makes up to three distinct nearest-next orders. It supplies no road graph, walking duration or access validation. `transport.js` already supplies cancellation, deadlines, serial requests and a bounded cache.
- `src/home/main.js` currently changes nearby results through named-place selection. Its `isDetailed` coordinate check selects the existing Kyoto scene. Extending map discovery should preserve the distinction between the map camera center and the selected named place.
- The detailed Kyoto world has explicit 64 m bounds in `src/content/kyoto.js`. `src/simulation/world.js` clamps movement to a rectangle; click travel in `src/simulation/index.js` uses one mapped crossing. These rules cannot serve as a global pedestrian simulator. The current `public/models/shijo-block.glb` is **14,267,180 bytes** on disk; that is one asset measurement, not a representative city-size estimate.

OpenMapTiles explicitly describes `render_height` as an approximation. Its current building layer offers geometry and rendering attributes; the richer OSM tagging scheme includes optional levels, facade materials and roof shapes, which may be absent or unavailable in a particular tile schema. Preserve the available source fields and provenance rather than inferring a complete building from a footprint. [OpenMapTiles schema](https://openmaptiles.org/docs/schema/), [OSM Simple 3D Buildings](https://wiki.openstreetmap.org/wiki/Simple_3D_Buildings)

COLMAP reconstructs from overlapping photographs taken from different viewpoints. Its guidance calls for texture, comparable illumination and substantial overlap, and identifies reconstruction and simplification stages. Its BSD license covers the program; image rights and dependencies are separate. These requirements underpin the higher production estimate. [COLMAP tutorial](https://colmap.github.io/tutorial.html), [license](https://github.com/colmap/colmap/blob/main/LICENSE)

## Implementation proposal

1. **Keep one spatial identity model.** Use WGS84 source coordinates and stable provider IDs. Store `mapView` (center, zoom, bearing, pitch) separately from `selectedPlace` and `exploredArea` (center, radius, query time). Panning changes the view. “Explore this area” makes a deliberate bounded query. A camera center receives the label “Area center”; an actual returned source record supplies a place name.
2. **Use one art system across coverage levels.** Own a versioned MapLibre style referencing the configured provider, with the same colors, typography, source controls, focus indication and motion preferences as Kyoto. Keep a consistent meaning for map volumes versus detailed authored scenes. Do not add random shop signs, entrance assignments or local architectural details to create apparent realism. The color module described below implements the shared palette; its browser presentation awaits integration and QA.
3. **Create data-based area packs when justified.** Proposed fields: `id`, `version`, geographic bounds, local projection/origin, source/license/date manifest, source features with stable IDs, optional reviewed landmark details, optional path/access evidence, optional authored interaction anchors and a performance budget. Keep `observed`, `derived` and `authored` values distinguishable. A corrected source record must be replaceable without rewriting the renderer. Store player notes and chosen views separately.
4. **Separate rendering from walking.** Global exploration initially uses camera movement and place selection. A future grounded walking layer requires connected footways, crossings, obstacles, grade/level handling and explicit treatment of missing widths or access tags. Raw OSM extracts or an appropriately hosted provider can support that work. Rendering tiles are not a validated navigation graph. Do not expand Kyoto's movement rectangle to simulate a second city.
5. **Make memory actionable.** Save a chosen sourced place with the map view and an optional personal reason to return. Reload should restore that place/view; Maps handoff should use the actual selected records. The record represents an intention or simulated exploration. Physical visits require a separate user report. Existing personal notes must remain private by default.
6. **Keep optional media independent.** A photograph/panorama record needs source, author, license, capture date if known, viewpoint identity and allowed transformations. Show its date and attribution when opened. A failed media request should leave the map and saved selection usable. No media, scan, new service or paid endpoint is introduced by this research.

For future distributed packs, PMTiles supports a versioned tile archive read through HTTP range requests; changing an archive requires rewriting it. It is a possible packaging method after an actual need for owned extracts exists, not a requirement for the current online-map pilot. [PMTiles documentation](https://docs.protomaps.com/pmtiles/)

## Provider and rights boundaries

OpenFreeMap currently permits free commercial public use without registration or keys, supports custom style JSON, and offers no SLA. Its terms dated **14 October 2026** restrict automated collection, with an offline-download allowance of at most **3,000 tiles or 50 MB**, at most four parallel requests and an identifying User-Agent. Use its online display path or the documented bounded download allowance; plan owned extracts separately for large-scale pack production. [Service](https://openfreemap.org/), [style guide](https://openfreemap.org/quick_start/), [terms](https://openfreemap.org/tos/)

OSM-derived data requires OSM attribution and ODbL handling. Preserve database licensing separately from independently authored code and art; a source manifest should state the relevant data license. OpenMapTiles also requires attribution for its schema. [OSM copyright and licensing](https://www.openstreetmap.org/copyright)

Photon's demo service allows reasonable project use and may throttle extensive usage; it provides no availability guarantee. Wikipedia geosearch returns nearby articles, so article presence and coordinates remain provider evidence rather than official attraction/access validation. Retain current respectful request behavior and explicit errors. Public Overpass guidance identifies a general consumer app relying on its public instances as problematic; a future geometry pipeline needs an appropriate data supply. [Photon README](https://raw.githubusercontent.com/komoot/photon/master/README.md), [MediaWiki geosearch](https://www.mediawiki.org/wiki/API:Geosearch), [Overpass guidance](https://dev.overpass-api.de/overpass-doc/en/preface/commons.html)

Commons media must be checked per file for author, license and any additional rights. Optional original captures need their own publication permissions. Google Street View API content has attribution and storage restrictions; Google Map Tiles content is licensed for visualization and restricts extraction and offline use. Those API terms do not grant a general source for generating our own scene geometry or textures. API-specific restrictions should not be presented as a blanket claim about all human visual reference. No Google media was fetched in this work. [Commons reuse](https://commons.wikimedia.org/wiki/Commons:Reusing_content_outside_Wikimedia), [Street View API policies](https://developers.google.com/maps/documentation/streetview/policies), [Map Tiles policies](https://developers.google.com/maps/documentation/tile/policies)

Proposed acceptance task for each area: orient using the visible water/green/street structure, move to a personally interesting nearby area, explicitly request nearby places, choose a source-backed result, save the view/reason, reload, and open the chosen stop order in Maps. This tests the same interaction and art rules against two different urban forms. It does not require two custom city models.

Acceptance checks: map movement alone produces no nearby-search request; explicit exploration searches the current view center and shows radius/source status; cancellation prevents a previous area overwriting the current one; no-results and provider-denial states preserve the map and private saves; selected records retain identity/coordinates through Maps handoff; English/Chinese navigation and source notices remain consistent; saved views survive reload; the known Paris conflict stays excluded. Browser checks must record transferred bytes, rendering responsiveness and recovery on the same desktop/mobile configurations used by the quality sprint. Targets should be set against that measured baseline rather than invented city-wide performance guarantees.

The remaining decision is the pilot's movement presentation: the recommended scope is map-camera exploration with deliberate area discovery and personal continuity. Ground-level avatar traversal and scanned places require their own data and quality criteria.

## Shared map palette module

`src/home/map-style.js` defines `TRAVEL_MAP_STYLE_ID = 'tourguideai-travel-map-v1'` and exports `applyTravelMapStyle(map)`. Call it inside every `style.load` callback, including a retry after `setStyle`. It preflights the captured Liberty layer names/types and then assigns color paint properties. Repeated calls assign the same values. A missing or incompatible layer throws before any paint update; the integrating map should use its existing explicit error/retry presentation.

The warm stone, sage vegetation, blue-grey water and cream roads are authored colors. Road widths, dashes, filters, source data, building height/base, label layers, attribution and light settings retain their provider configuration. Road/tunnel/bridge classes share a palette while their original geometry rules remain. The module's layer assumptions are tied to `openfreemap-liberty.json` in the research evidence. `tests/map-style.test.mjs` checks those actual layer identities and validates the resulting style through MapLibre's installed style-spec validator. Browser integration, appearance and retry checks belong to final QA.

Official technical basis: [MapLibre `setPaintProperty`](https://maplibre.org/maplibre-gl-js/docs/API/classes/Map/#setpaintproperty) sets paint values on a named layer; the [style specification](https://maplibre.org/maplibre-style-spec/layers/#fill-extrusion-color) distinguishes extrusion color from its height/base properties. Sources checked 2026-10-18. No geometry or real-world lighting accuracy is added by this palette.
