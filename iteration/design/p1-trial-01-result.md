> **受试者**：用户本人（**而这是唯一合格的受试者**——团队成员都读过规格）。
> **对象**：`http://127.0.0.1:8088/`，变体 **V-A（bare）**，烘焙 `scene DDA21AF92ABD…`
> **截图**：HUD 那一行完整可读；画面本身近乎空白。

## 结果（**逐字记，不解释**）

> **「完全看不懂在干啥，界面太简陋了，没有任何目标提醒」**

**⇒ 拆成规格里的两个探针**：

| 探针 | 规格里它问什么 | 结果 |
|---|---|---|
**探针 A** | **你能说出屏幕上任意一个【真实地点】的名字吗？** | **未通过**——受试者没有说出任何地名，**而 HUD 里那个名字（`四条烏丸交差点 東側横断歩道 ±15 m`）他没读出来，或读了而它不算"屏幕上的地点"。** |
**探针 B** | **屏幕上有没有东西在告诉你"下一步该去哪"或"为什么要去"？** | **干净的"没有"**——**"没有任何目标提醒"** |

**⇒ 而这条负结果落进 §8.6 的 2×2 是哪一个格**：

```
A（意图）：画面里没有"为什么"  ⇒ A 在场（缺席）
B（赏金）：未测 —— 受试者没走到任何门
⇒ 两行都不到位：A 是"没有理由"，B 是"没被问到"
⇒ 按规格，这不是"不可归因"，是【A 缺席 · B 未达】
```

---

## 而截图本身给出的两条独立证据（**不依赖受试者的自我报告**）

**① 首帧的世界层内容 ≈ 4 个图元，而其中没有一个"可辨认的地方"**

```
左边一块灰绿矩形        = 建筑脚印（block 0 的北侧）
中间一个黑三角          = 走者（朝向标记）
一条细绿线              = 街道中心线
右边一个蓝色空心方框    = 一个锚点标记（在窗口右边缘）
其余整个画面            = 底色
```

**⇒ `play-systems-designer` 的预测在实测里成立**：**首帧没有任何东西读起来像"一个地方"。** 而它当时说的原话是：**"若 A 在场，我就是在【一屏读不出地方的画面】背后造内容。"**

**② 一个我们此前没量过的数：HUD 说"东行 5 m"，而最近的地点在 ±15 m。**

**⇒ 出生点往前挪了 5 m（镜头滑动所做的），而最近的真实地点仍在 15 m 外** ⇒ **首帧的【世界层】与【HUD 层】说了两件不同的事**：HUD 说得出"最近是四条烏丸交差点東側横断歩道"，**而画面里那个东西只是一个 32 px 的蓝框，没有任何可读的身份。**

**⇒ 这正是 `§8.6` 记的那条：`P10` 是词的检查（HUD 里有一个真实名称）、`P16` 是像素的检查（锚点格里有它自己的标记色）——两条都绿，而人仍然读不出来。** **⇒ 两条断言都不覆盖"这个东西看起来像不像一个地方"。**

---

## 它对 §8.6 那条"顺序陷阱"的处置意味着什么

**规格原本的顺序是：`eligible` → 边缘指示器 → 状态读数 → …… → 真人测试。**
**⇒ 而实测说明：即使上面全部到位，画面本身读不出来。** **⇒ 所以"边缘指示器"（一个指向目标的箭头）不会解决问题**——**它会让"往哪走"变得可读，而"这里是什么地方"仍然不可读。**

**⇒ 这不是"指示器没做"，是【指示器回答的问题不是受试者问的问题】。** **受试者问的是"这是啥、我在干啥"，而指示器答的是"往哪走"。**

## 受试者的第二条回答，我认为比第一条更值

> **「有看过 google 的实景地图界面设计吗，和预想的完全不一样」**

**⇒ 而它指向一个我们文档里从来没有的东西：【画面该长什么样】的参照物。** **受试者心里有一个，而我们的判据全都只问"有没有"**（有没有名字 · 有没有标记色 · 有没有计数），**没有一条问"看起来像不像"。**

**⇒ 而按它给的参照去核我们自己的规格，结论是**：

```
规格（appendix-visual-and-ui-spec.md L11，四项既定约束之一，「照单执行」）：
    家族 (b) 3/4 俯视分层
  L20  投影 θ = 70.53°（cos θ = 1/3）——「推出来的：3.0 m 层高 × 1/3 = 32.0 px = 正好 1 格 = 1 个立面带」
  L21  立面预算：带 1–6 = 3–18 m = 32–192 px
  L37  图层栈与唯一排序公式：depth = round(baselineY) × 16 + lane（上限 23,567）
  L46  竖立道具（售货机 / 植栽 / 立牌 / 电线杆 / 雨棚）→ 立面墙 → 挑出物与屋檐
  L75  facade 组合子集：带(1–6) × 3 格开间模板 × 开口类型（门/窗/卷帘/暖帘） × 顶部
  L79  京都示范：街具 = 成组售货机 · 暖帘 · 提灯 · 自行车列 · 电线杆 + 架空线（「日本街道最强的剪影信号」）· 町内会告示板

实现（bake-viewer.mjs + 那一屏）：
    0 个立面 · 0 个分层 · 0 个街具 · 0 次深度排序
    世界层 = 地面矩形 + 街道中心线 + 一个走者三角 + 32 px 空心蓝框
```

> **⇒ 所以受试者看到的不是"简陋的美术"，是【一张平面图】。**
> **⇒ 而这与"美术资产 0 个"是两件不同的事**：**资产是"画什么"，而这一处是"怎么画"——3/4 俯视 + 分层 + 立面，都可以用矩形画出来，不需要一个资产。**
> **⇒ 而 `heights` 字节就在 `scene.bin` 里（64,000 B 的一层），`bake-viewer.mjs` 读它（L132）、放进 payload，而【不画】。**

**⇒ 这条对 `play-systems-designer` 那个 2×2 的影响**：**它说的"可读性支（公共空间层 / 镜头）"是对的，但它比我以为的更基础——不是"再加一层公共空间"，是【把规格里已经写明的画法画出来】。**

## 记录（**R3：否定状态**）

- **P1 未通过。** 这是它有史以来第一次被真实执行，而它**红在一个我们没写进判据的地方**：**判据问的是"30 秒内知道做什么、第一次按键有回应"，而受试者的回答是"完全看不懂在干啥"——那是比"不知道下一步"更早的一层：不知道【这是什么】。**
