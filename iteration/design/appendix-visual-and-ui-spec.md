## 1. 视觉语言规格

四项既定约束照单执行：家族 (b) 3/4 俯视分层、Phaser 4.2.1、新城市不得新增 tile 类型、起步 CC0 模块化套件 + 仅地标买手绘。内容单位 = **门洞与门后的内部空间**。

### 1.1 网格 / 比例 / 投影 —— 全部是 config 常量

| 项 | 值 | 推导（不是偏好） |
|---|---|---|
| 格子 | **32×32 px** | LimeZu 内外景同源出 16/32/48；Cozy People 的 20×16 精灵正画在 32×32 格里。16 装不下「3 m 店面 + 12 px 汉字」，48 让美术面积 ×2.25 而可读性零收益 → **只收 32 一档进管线**，一格、一图集、一碰撞栅格 |
| 世界比例 | **1 格 = 1 m** | 店面模块 = 3 格 = 3 m |
| 街区 | **40×40 格 = 1280×1280 px** | 一条 40 m 街；店面模块 26 个（2 侧 × 40/3），其中 **12 个可进入 = 46%** |
| **投影** | **θ = 70.53°（cos θ = 1/3）** | **推出来的**：3.0 m 层高 × 1/3 = **32.0 px = 正好 1 格 = 1 个立面带**；1.7 m 人 = 18.1 px（16 px 精灵短 13%，可接受）。纵向换算 = 米 × 10.67 px |
| 立面预算 | 带 1–6 = 3–18 m = 32–192 px | >18 m 用 `topEdge:"cut"`，其上天留空。**城市识别度在带 1–2，不在带数** |
| 汉字 | 最小 **12×12 px**（世界）→ zoom 2 屏上 24 px | 32 px 格内留 10 px 边距，64 px 招牌放 4 字；**字号只有 12/14/16 三档**（位图字形图集），以控制子集与缓存键 |
| 运动 | 街 1.2 格·s⁻¹、室内 0.8；进入判定距门锚点 **≤1.5 格（48 px）** | 碰撞盒 24×16 px 锚在脚印底中点 —— **「走到墙后头被遮住」是特性** |

### 1.2 摄像机（zoom 只允许整数，非整数会让像素抖动）

canvas 1280×720 logical、`Scale.FIT`、nearest、`roundPixels`；跟随 deadzone 192×96 px、lerp 0.1、边界 = 地图 +1 格。

| zoom | 可见世界 px | 可见格 | 用途 |
|---|---|---|---|
| 1 | 1280×720 | 40 × 22.5 | 只用于拍照/攻略截图与调试地图，静止 |
| **2（默认）** | 640×360 | **20 × 11.25** | 街道 **和全部室内** |
| 3 | 426.7×240 | 13.3 × 7.5 | 研究/拍照模式（对准招牌） |

**硬规则**：室内模板 ≤ 16×10 格（S 10×7 / M 13×9 / L 16×10）→ 任何室内在 zoom 2 下一屏装得下，**室内永不滚动**。一屏 = 一个门后的内容单元。

### 1.3 图层栈与唯一排序公式

`depth = round(baselineY) × 16 + lane`，上限 (1280+192)×16+15 = **23,567**；所有精灵 origin (0.5, 1.0)。

| lane | 内容 |
|---|---|
| 0 | 地面 tilemap —— **GPU 层**：整层单一 depth（不参与排序），正交图 1 draw call，单张纹理上限 4096² **px**，而本项目走廊地面共 **80,000 格**（2000×40）。⚠️ **不是"只用 40²"**——40×40 只是**一个手作街区**那一层；两者是**不同的量**，混用会在第一次做地图时炸掉（见 `design-core` §8.2.1 ⑤ 与 `contract-geo-pipeline.md`）。地面共 81.92 Mpx，RGBA 上屏 = **312.5 MiB（= 327.68 MB）** → **必须以索引色 + 调色板上屏** |
| 1–2 | 地面贴花（井盖/路面漆/水篦）→ 平置道具（footprint ≤0.25 m：门垫、自行车位标线） |
| 3 | **实体**（玩家/NPC/车）；同 lane 内按 entityId 升序决平手 → 确定性 |
| 4–6 | 竖立道具（售货机/植栽/立牌/电线杆/雨棚）→ 立面墙 → 挑出物与屋檐（按**挑出物自己的**脚印行排 → 前挑 1 格的招牌自然排在它后面的墙之前） |
| 7 | 招牌自发光（additive，夜间不受 tint 影响） |
| 8 | 天气/氛围粒子 |
| 9 / 10 | HUD（React DOM，z-index 100）／文档层（攻略·回忆录，z-index 200） |

**规则**：任何精灵的像素**不得画到自己脚印底边以下**；向下挑出者必须拆成独立精灵。
（这是 Jettelly「元素必须待在格内」约束的正交版本：**0 美术预算，但最贵于返工**。）

### 1.4 调色板与光照

每城 **4 个自由角色 + 1 个锁定角色**：
`ink` 锁定 L\*10 = `#16161D`（对纸 **16.12:1**，AAA）；`groundBase` L\*42±6；`wallBase` L\*62±6；`accent` L\*52、C\*≥40（例：京都 `#9B2D2A`，对纸 **6.71:1**）；`glow` L\*78 供夜间加色。

美术只挑 4 个种子色，`palette.mjs` 展开成 4 级（ΔL\* = −14/0/+11/+20，色度顶端 −18%），校验器断言 L\* 落在 ±3 → **「换调色板」机械可验，不会糊成一团**。

光照**不逐格烘焙**：4 个时段各一组乘算 tint 打在 lane 0–6，lane 7 免疫。晨 (1.00,0.96,0.88)／昼 (1,1,1)／暮 (1.06,0.94,0.78)+发光／夜 (0.72,0.78,1.00)+全发光；切换 600 ms 交叉淡入（日 = 120 tick × 7 s = 14 min 实时，每 3 h 换一次 = 126 s，600 ms 占 0.5%）。
**静态背景根本拿不到昼夜——这是选家族 (b) 白送的，必须用上。**

## 2. 风格包（style kit）定义

`city-packs/<city>/style.json`，六块，缺一块即 schema 失败：

| 块 | 内容 |
|---|---|
| `palette` | 4 个种子 hex + 角色绑定（§1.4） |
| `typography` | **2 种字体语域**：黑体（连锁店/交通/站牌）／明朝体（寺社、老铺、和食）。竖排（縦書き）作为**招牌默认排版**。kit 只选语域，**不得改字号、字距、档位** |
| `props` | 6–10 个街区道具，从共享 `props.json` 取，或在 `localProps[]` 声明（≤10） |
| `facade` | 允许的立面组合子集：带(1–6) × 3 格开间模板 × 开口类型（门/窗/卷帘/暖帘） × 顶部（女儿墙/招牌墙/坡屋顶）+ 每带权重 |
| `roof` | 平顶女儿墙/双坡/四坡/折面 + 附着物（水箱、天线、招牌钢架） |
| `ambient` | 3 条环境音 + 1 条氛围粒子 + 时段发光规则（哪块招牌几点亮） |

**京都示范**（读成"这座城"而非泛用城市）：街具 = 成组售货机（2 台）、暖帘、提灯、人行道边界的自行车列、**电线杆 + 架空线**（日本街道最强的剪影信号）、町内会告示板；立面 = 低层 2–4 带、**第 1 带几乎全是开口**（zakkyo 多租户密集感）、暖帘与雨棚挑出 1 格、细长竖招密排（0.6 格宽 × 2–4 带高）；环境线索 = 平交道口音、站内发车旋律、**17:00 防犯放送**（日本独有的声音时钟，等于免费的时间流逝提示）。

### 充分性测试（可检查，不是愿望）

- **SK-1 结构性**：`node tools/validate-city-kit.mjs city-packs/<city>` 退 0。断言
  (a) 地图每一格 `tileId ∈ tiles.json`（hash 锁定）；
  (b) 引用的每个 `propId ∈ props.json` 或在 `localProps[]` 且 ≤10；
  (c) `style.json` 过 schema；(d) 每个角色色能展开成合法 ramp。
- **SK-2 行为性**：`MASK_KIT=1` 构建 → 关掉全部 kit 局部道具与调色板，换词表默认值，必须仍退 0：
  (i) 从出生点洪泛可达全部 12 个门口；(ii) 零个未贴图格；(iii) 每块招牌渲染成词表占位形。

**解读**：**SK-1 失败 = 真的需要新 tile 类型 = 设计缺陷**；**SK-2 失败 = 这座城市离开装饰就结构不完整 = 风格包在承重 = 设计缺陷**。两条都在 CI 里跑，不是评审意见。

## 3. HUD 与两个非游戏界面（一套 token，三个界面）

**共享 token**（CSS 变量 + TS 镜像，`--city-*` 由 §1.4 注入）：
`--ink #16161D`（对纸 16.12:1）｜`--paper #F6F2EA`｜`--city-{wall,ground,accent,glow}`｜可信度三态 `--ok #1F6B3A`（**5.84:1**）/`--warn #8A5A00`（**5.31:1**）/`--unknown #6B6B6B`（**4.77:1**）——三色全部过 AA｜间距 `--step-0..5` = 4/8/12/16/24/32 px（唯一刻度）｜圆角 0（世界与 HUD）/2 px（chip）/4 px（卡片），**像素画不用圆角与投影**｜时长 120/240/600 ms｜`--font-ui` = 拉丁 + 玩家母语子集，**UI 字体永不装日文**。
构建期 `palette.mjs` 断言全部文字 ≥4.5:1、chip ≥3:1。

### (a) 游戏内 HUD —— 屏幕空间 React DOM（**不进 canvas**）

```
┌ Day 2 · 14:20   ▓▓▓▓▓▓▓▓▓▓░░░░░░░░        ┐  左上：日/时 + 20 格日弧（1 格 = 1 游戏小时，6:00→2:00）
│                                  ▲ 末班 23:30│  另加当前目标的关门刻痕
│                             ¥12,480   −230 │  右上：整数日元；变动量 3 s 淡出
│   [E] 进入    [Space] 拍照                 │  世界空间：门上方 16×16 雪佛龙 + 门名的母语 chip
│  体力 ●●●○○  Rested                       │  （世界锚点投影到屏幕、10 Hz 节流 → 文字永远清晰）
│  目标：16:30 前到金阁寺（16:00 停止入场）    │  左下 5 格 + 词；底部居中单行 ≤48 字 + Plan B 折叠
└ 📱 96×160 折叠胶囊 ⇄ 640×400 暂停面板      ┘  右下：查词/拍照/地图都在这台「手机」里
```

只有世界空间的可交互提示归 `OverlayScene`。

**刻意不出现**：小地图（40×40 m 的地图比它描述的地方还大）、任务日志、背包格、血条/体力战斗条、等级与经验、常驻商城、通知流、罗盘、发布版帧率与版本号、**以及任何「翻译」按钮**（那正是字符串表泄漏）。
**HUD 里唯一的日文，只能出现在带 gloss 的查词卡内。**

### (b) 攻略 `/guide` —— DOM + print CSS

单文件离线 HTML，零网络请求，`file://` 可开，**目标 <400 KB（含子集字体）**。
结构：封面（打印 GuideDoc hash `doc:3f9c…`）→ 日程卡 → 地点卡 → 语言卡 → 交通卡 → 附录。
纸面 A4、边距 24 mm、正文栏 162 mm；**地点卡双栏 78 mm + 6 mm 中缝**，日程卡单栏；手机单栏正文 16 px。

溯源 chip 是**固定 3 形组件，语义由形状而非 emoji 承载**（emoji 打印不可靠）：
实心圆 `已到 · 2026-03-14`｜半圆 `已核实 · 来源 · 2026-03-01`｜空心三角 `待确认`。
`verified_at` 永远打印 ISO 日期；半静态/动态事实必须带 Plan B 与缓冲。
**确定性**：同一 GuideDoc → **逐字节相同 HTML**（所以 hash 能印在封面）。
另出 A5 折页口袋版，只含日程卡 + 语言卡。

### (c) 回忆录 `/memoir` —— 12 栏网格，跨页 = 2 × 6 栏

两类素材：游戏内截图（16:9，随当前 zoom：zoom 2 → 640×360 世界像素 ×2 = 1280×720）与玩家真实照片（任意比例）。
真实照片**默认只等比缩放进 4:3 或 3:4 框、用 `groundBase` 实体条补边、绝不裁切**；裁切是逐张显式动作。
配对规则确定性且遵守 drop-don't-correct：同地点内 **EXIF 时间差 ≤±45 min 且 GPS ≤150 m** 才配对，否则真实照片独占并挂「未匹配」chip；**无 EXIF 的照片永不猜地点**。
顺序按 tick / EXIF，不按上传顺序。导出走与攻略同一条离线单文件管线 + PDF（跨页 200×250 mm）。

## 4. 语言障碍的渲染

一份状态 `knownGlyphs: Set<GlyphId>` 同时驱动**渲染**与**字体子集**——不是两套系统同步，是**同一个文件在生成时被读两次**。

### 对 recon §4E 的一处收紧（关键）

recon 说子集 = 攻略所需 ∪ 已学。**这在游戏内是泄漏**——玩家打开攻略就看见了没学过的字形。故拆成**两个子集、两个消费者**：

| 文件 | 内容 | 消费者 |
|---|---|---|
| `world.woff2` | **仅已学** | 游戏渲染 |
| `guide.woff2` | 已学 ∪ 攻略所需 | **仅**导出文档 |

同一 `pyftsubset` 产出，但**不是同一个文件**。
字体选 **Noto Sans CJK / Source Han Sans，SIL OFL 1.1**（OFL 无 share-alike 传染，但须随包保留许可声明、不得单独售卖字体本身）。

### 未学字形画什么 —— 三个选项里只有第三个不读作 bug

1. tofu 方框 → 立刻读成缺字/编译错误。**否。**
2. 「？？？」→ 读成字符串表占位，等于承认这是字符串表。**否。**
3. **模糊母版（squint master）**：同一批字形离线降质成 6×6 px 墨团再放大，只保留**墨量分布**，用同一个 `ink` 角色色、同一套抗锯齿渲染。于是未学的汉字**不是方块，是形状正确、笔画数可辨的灰墨团**——这正是非读者眼里的日文招牌。信息通道没被堵死，只是变贵（可数笔画、可猜「这是拉面店」）。

**学习动作**：研究模式拍照 → 该字形 **400 ms 锐化交叉淡入**（含 2 帧回弹）+ toast + `knownGlyphs` 落盘。**状态 +1 与字形变清晰是同一个事件。**
**gloss 覆盖**：玩家自己的猜测以 `--font-ui` 斜体、60% 不透明度小上标 chip 画在墨团上方；**猜错也照画，游戏按「玩家以为的意思」行动**（点错菜、上错车）——机制在这里被看见。

| 阶段 | 状态（按**招牌面积加权**的字形覆盖率，不是字数） | 街上看起来 |
|---|---|---|
| **0%** | 0 字形 | 全部汉字假名成墨团；但**罗马字副文、数字、价格、logo、暖帘色块全部清晰**。真实日本街景招牌面积里本就有 15–25% 是拉丁字母与数字 → 画面**永远含有锐利文字**；锐利外框 + 柔化内核读作景深/语言，不读作丢贴图 |
| **30%** | 假名 + 城包内前 60 个高频汉字（由普查脚本产出，**非估计**） | 假名全锐，语法可读、词义靠猜：「さっぽろ」锐、「名物」成团 → 读懂句式、拿不到宾语；gloss chip 开始密集，猜错开始有代价 |
| **80%** | ~450 字形（招牌普查目标值） | 街面基本解析完，墨团只剩在**难字、专名、公文**上：告示板、售票机运费表、诊所问诊表。**视觉上很平静，机制完全没变**——阶梯不是「街越来越可读」，而是「**最后 20% 才是真正要紧的内容**」 |

**防「读作 bug」清单（可检查）**：① 墨团绝不均匀，川(3 画) 明显比 議(20 画) 淡——**墨量方差是特性**；② 拉丁/数字/价格永不模糊；③ 形状跟源字形（ー 与 一 是横条，口 是方块），不是统一方块；④ 墨团与锐字共用同一抗锯齿路径与同一 `ink` 色；⑤ 每次状态变化必有动画，无静默突变；⑥ 悬停墨团显示「?」+`未学习`（UI 字体）= **陈述**而非占位符；⑦ `tools/glyphCoverage.mjs` 扫城包全部招牌串，断言每字形 ∈ known ∪ blobSet；`F9` 把墨团描品红边，**品红框内出现锐字即 bug**。

设置里**没有语言选择器**（只有 UI chrome 的 i18n 走 i18next）。判据照 §4E：**UI 语言切英文，场景内文字一字不变。**

## 6. 该专家的分歧（原文要点）

**最贵的不是美术，是招牌与字形管线：60–90 小时——而这个方向里所有人（包括提问者）都把它当成「用个字体，那是个设置项」。** 它不是一个功能，是四件互相咬合的事：城市招牌普查与排版（竖排、三档字号、三语混排）、模糊母版生成、两个子集的构建与缓存、逐字形笔画数。其中**模糊母版是全规格里唯一没有现成实现的东西**：`pyftsubset` 只会裁剪、不会降质，「栅格化 → 模糊 → 矢量化」得自己做一遍——**2–3 天的未知数，可能翻倍**。而它恰好落在「感知上最大的城市差异、最不被通用素材包覆盖」那一项：**省不掉，也没人卖。**

**次贵**：深度排序与「挑出物」约束。它现在免费，代价是从第一天起就禁止任何越过脚印底边的美术；**第 200 张图违反它时，返工的是整套图集。**

**被迫接受廉价替代时**：放弃字体管线，改用**预渲染汉字图集**——一张 300 字形 / 16 px 图集（按已验证价目表委托专业档小 tileset **$150–400**，或自绘 ~20 h），墨团 = 同一图集 22% 墨量版。机制**一字不改**（「字体子集」退化为「图集页常驻」，状态仍是同一个集合），`pyftsubset` 只留给攻略子集。代价很具体：没有真排版与字距、字形数被冻结在图集里、观感像 90 年代主机。**该专家表示会接受它**——因为它删掉了唯一没有参考实现的那一步，而机制完好。
