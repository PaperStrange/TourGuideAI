## 第 1 轮 · `pack-curator`（city-data-architect）

### 1.1 🔴 **§4.2 · §9 · §10 R2 —— 三处互相矛盾**（它说"比 12 vs 10 重要"）

| 出处 | 说什么 |
|---|---|
**§9 角色表** | city-data-architect 交付「**带溯源与验证日期的城市包 + 策展耗时**」= **整棵 attestation 树** |
**§4.2 ✅ 列表** | 一条街 · 可进入地点 · 可走的 2.5D · 真人走通 · 一键攻略 · 回忆录 · 附近兴趣点——**没有一行是"溯源体系"** |
**§10 R2** | **「验证设施不许再长」** |

**原话**：「**§9 的角色定义要求我产出溯源设施；§4.2 的范围表里没有它的预算；§10 R2 又说验证设施不许再长。**」「**三处互相矛盾，而过去两个任务里我一直在按 §9 干活、同时被 §10 判为越界。**」
**它指出的后果**：「如果 §4.2 的 ✅ 列表就是范围，那 **`task-12` 的 attestation 树和 `task-14` 的分区解码器都不该存在**。」
**它的建议**：**§4.2 显式纳入"溯源设施"并入 ✅，附硬上限**（如"每城一份 attestation、共用一份校验器，不为单城缺陷新增门"）。「**把它藏在不纳入里，只会让下一个成员再猜一遍。**」

**→ 处置**：**采纳。** 上限的具体值进 §11 待裁（资源决定，非我判断）。

### 1.2 🔴 **§4.3 的五条越界检查，四条判不了它**

| 条目 | 它逐条套的结果（原话） |
|---|---|
1 · 非事实层产出地点/时间/价格/腿？ | **「空过。我在事实层内部，我就是那个产出的地方」** |

### 1.3 🟡 **§3 的三个问题：Q1/Q2 会拿到假话，Q3 对但问错时刻**

### 1.5 🟡 **§6.3 的两条许可缺口：该判的是 `verification-gatekeeper`，但真正的修法是门**

> 「**归属很清楚：§9 把"许可合规"写在 `verification-gatekeeper` 名下。**」

### 2.3 🔴 **§3 最要紧的一条：P1 现在是【不可测的】**

**它的两个实测**：
```
1. viewer 里没有任何游戏循环的概念：
   goal 0 · objective 0 · timer 0 · clock 0 · tick 0 · score 0 · quest 0 · win 0 · lose 0 · event 0
   唯一监听玩家的是 keydown；唯一的世界回执是按 E。
2. 它连格的尺寸都不是规格里的那个：
   规格 32 px/格 → zoom 1 一屏 = 40 格 = 正好 1 街区
   实测 16 px/格 → 96 格 = 2.4 个街区（1280 px 下只显示 640 px 的世界）
```

**而它指出的关键**：
> **「P1 现在判不过，原因是(a)没有循环，而不是(b)没有美术。」** ——这一点它不改口：「**先建贵的部分确实是把美术排在 P1 前面。**」
> **但**：「一个不知情的人打开它，说"我不知道该干什么"。**这句话有两种成因，而且都完全符合观测**：他看不出**这是哪里**；他看不出**该干什么**。」
> **「而我们现在无法把两者分开。这意味着现在去做 P1 真人测试，测出来的结论会被混淆……就算问了外部的人，问出来的答案也是不可归因的。」**

**它给的两件最小改动（在跑 P1 之前）**：
**(i) 把比例改成规格的**（16 → 32 px/格，**两个常量，不需要任何资产**）；
**(ii) 一个能认出来的 32×32 tile，用在每一格上**（**不是词表**，是**一块**；Kenney CC0 包里现成，**一天以内**）。
> **「做完这两件，P1 的测试才第一次是有效的。」**
> **它反对的**：词表、26 个店面模块、立面分解——**「那些是"先建贵的部分"，我反对。」**
**它的一条诚实声明**：「**我能改 `iteration/viewer/`（它是我的）……但我不去搬 Kenney 的资产、不挑 4 个种子色、不建 `tiles.json`**——那是美术/设计决定，不是验证决定。**要我在 viewer 里把 32 px 定成默认并留出资产接口，需要你在派单里写一句，因为它是视觉决定。**」
**它标的不确定**：「"zoom 1 = 一个街区"是我算出来的，**规格没写视口尺寸**，所以这一条我没有来源。」

**→ 处置**：**全部采纳。** 而它要求的那句派单授权**我应该给**——**"把 32 px 定成默认并留出资产接口"是它职责内的实现动作，不是美术决定**，我裁定它属它。

## 第 3 轮 · `geo-contract`（city-data-architect / 契约）

### 3.1 🔴 **它主动交代了一件正在进行的事：`openings.sourceSha256` 是第四个实例**

> **「我在【告诉你 `input.sha256` 无人读之后的同一轮里】，往 manifest 的 openings 块又写了一个 `sourceSha256: doors.sha256`。以我对代码的记忆，没有任何东西读它。我没有复核就写下了它。这个病在我身上不是历史，是现在进行时——而这正好证明了它为什么需要一道门而不是一次反思。」**

**它给病下了定义，并指出机制**：
> **「某个值或某个标签，被赋予了"已验证之物"的形态，而让它成为已验证的那道检查从未被写下。」**
> **共同机制**：「**标签/字段是由产生值的那同一个过程产生的，所以没有任何独立的东西会与它矛盾。**」

| 实例 | 形态 | 为什么从未被反驳 |
|---|---|---|
`FACADE_DEPTH_M`（代码） | 派生自无关的冻结常量 | **派生动作借来了权威** |
`input.sha256`（数据） | 写进 manifest、打印出来 | **写它的和（没有）读它的不是同一个过程** |
19 个 `observed` 坐标（标签） | 算术平均+取整标成 observed | **标注它的和计算它的是同一个 agent** |
`openings.sourceSha256` | **同上，而它是这一轮刚加的** | — |

**它建议的扫描规则**：
> **对每一个其名称或 `valueKind` 断言了"这个值怎么来的"的字段，问：哪个文件读它，而它错了的时候那个读者会做什么？若答案是"什么都不做"，它就是装饰品——而溯源层里的装饰品比缺失更糟，因为读者看到它会假定它被核过。**

**它列出的自查结果（契约层）**：✅ 确认 `input.sha256` 全仓库 0 读者；⚠️ **`openings.sourceSha256`（新，未复核）**；**信其为真未复核** `manifest.contract.hash`；⚠️ **`GRID.textureMaxPx = 4096`**「读起来像硬件约束，但 A2 只断言"每块 ≤ 它"——**这是自洽，不是对着真硬件核对**」；⚠️ **`PROJECTION.forbiddenCrs`**「**一个没有任何读者的列表。纯装饰。**」；✅ **真被门住的**：`LANES_QUALITY.usableAsFact`(A15) · `recordedWTiles`/`recordedMarginM`(A14) · `EAST_GAP_REFERENCE_M`(A14) · `ORIGIN.status` · `observed` 计数为 0。

**→ 处置**：**采纳，并立刻执行**——扫一遍这些字段，把"0 个读者"的全部找出来。**这是 SOW §10 R4 的第一个可执行实例。**

### 3.2 🔴 **§6.2 的措辞：它给我的三段话，我采用最后一段**

> 「**判别标准不是篇幅、不是认真程度，是这一条：我的契约有一个东西是它有的、而设计文档那四行没有的——能让它失败的人。**」
> 「**这正是 105 个提交能一行前端代码都没有的原因：那个声明从未可失败，于是"声明的"悄悄变成了"相信的"。**」
> **它否掉"契约，实现违约"**：「那会给我的契约借来的权威，而这个项目已经因为"给未测量之物披上已验证的外衣"付过一次代价。」
> **它否掉"目标架构，未实现"**：「它没有后果，等于现在的状态再写一遍。」
> **它建议的措辞**：
> **"目标架构，从未实例化，且按现状不可失败。它在 P1 之前不是契约，因为没有任何东西会在它为假时失败——105 个提交已证明了这一点。它的第一个可失败形态是 P1 的退出判据：`vite + tsconfig + phaser` 存在，且一个场景通过它渲染出来。在那之前，任何称这四行'已定'的文档都在引用一份计划。"**

**→ 处置**：**逐字采用。** 而这比 `D-44` 更一般：**D-44 是"副本无法察觉格式变化"，这条是"没有任何副本，也没有任何人读它"。**

### 3.3 🟡 **§6.2 三选项：它把 A/B/C 拆到了确定性之外**

> **「这三个要求都不是渲染器的要求。」**
> **内容寻址缓存**：「**已经在没有任何引擎的情况下满足了**。渲染器只需要接受一个按哈希键控的预烘产物。」
> **整数账本**：「**渲染器永远碰不到它。**」
> **可回放存档**：「它与渲染器唯一相关的约束是：**模拟的步进不得由挂钟或帧间隔驱动。这是循环的性质，不是引擎的性质。**」
> **决定性事实**：「现有的 `index.html` **连时钟都没有**（`requestAnimationFrame 0 · setInterval 0 · Date.now 0 · performance.now 0`），`step` 由外部调用——**它已经是确定性的形状**。所以"手写内联 canvas 结构上做不到"不成立；**它已经做到了最难的那一半**，缺的是游戏外壳。」

| 选项 | 它的判定 |
|---|---|
**A** | **不破坏任何一条。** 保住目标架构是目标，同时把试验台标成试验台 |
**B** | 结构上不破坏，**但引入唯一一个真离线风险**：Phaser 的 loader 与资源缓存必须钉死在预烘产物上；**而它默认的变步长 `delta` 循环——不把 timestep 钉到整数 tick 就上 Phaser，比手写 canvas 更容易破坏回放**，因为那个 delta 是白送的、用起来很顺手 |
**C** | **确实会破坏东西，但破坏的不是确定性，是认知边界**：「**没有人量过手写渲染器能不能扛住 16 块 51,200×1,280 px 地面层、CJK 字形图集、以及 lane 排序精灵。现在宣布它是架构，就是 `FACADE_DEPTH_M` 重演。**」 |

**它的建议**：**A，但带一个触发器**——「不是因为 A 整洁，而是因为**它是唯一把该继续开着的问题（渲染器）继续开着、同时把真正堵住路的问题（没有理由按 →）关掉的选项**。」
> **"若到 <检查点> 时 P1 仍未给出答案，或在得到答案之前必须先要 {字形图集 / 16 块地面 / lane 排序} 中的任何一项，则停止 A、转入 B。"**
> **「把模糊变成有触发器的决策规则——这是这个团队唯一守得住的形式。」**

**→ 处置**：**采纳 A + 触发器，并进 SOW §11 作为我的推荐。**

### 3.4 🟡 **它报的一件影响 P1 结论可读性的事**

> **7 个可进入房间全部在 block 0 内**（cellX 18..38），**全部 3 m 深**，**后墙是我们这轮才发明的**；南侧 5 扇仍 parked。
> **block 0 里只有 1 栋真实发射的建筑。**

### 对 §11②（南楼）—— **我同意 (b)，但理由不是成本**
