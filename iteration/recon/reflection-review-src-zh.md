# 反思 · review-src-zh（L-C 中文评价平台条款横评）

写给 Lead，也写给之后接手的人。全部是我亲手做过的事和我的判断，不含对任务卡的复述。

## 0. 先回答你点名问我的三件事

### ① 快照还有效吗；三个月后哪几条先坏

**我抓的就是今天（2026-09-30），0 天。所以问题不在天数，在"版本可判定性"。**

13 行裁决里有结论的 11 条（9 个 UGC/交易平台 + 2 个维基项目）。**我只拿到 4 个版本日期，全是平台**：B站国际版使用协议 2020-04-08、大众点评用户服务条款 2022-12-05、去哪儿网用户服务协议 2026-05-01、飞猪法律声明 2019-08-06。**另外 7 条我拿到了文本，却定位不到它是哪一版**：携程、知乎、微信公众平台、穷游、豆瓣、美团知识产权声明、美团用户服务协议。这不是"过期风险"，这是**今天就已经无法判断是否过期**。

按"三个月后开工先重抓谁"排序：

1. **携程 —— 我最大的一条错。** 我引的是 `pages.c-ctrip.com/commerce/promote/201705/other/state/apph5/index1.html`，**2017 年的营销页路径**，页面无日期无版本号，我没有任何证据证明它是现行服务协议。重抓前，携程那一行应降级为"条文取自旧版页面"。
2. **哔哩哔哩。** 只有国际版；大陆版两条路径 404。**国际版与大陆版是否同文，我没有验证——未知不等于相同。**
3. **微信公众平台服务协议。** 无日期。而且我在写文件时**明确去找过版本日期、没找到，就略过去了**。引用一份定位不到版本的文件是失职，不该记成"缺口"。
4. **知乎。** 无日期；"不得用于大语言模型训练"这类禁令是近年才加的，说明这份文本在动。
5. **大众点评/美团。** 条款是 2022-12-05；我引的《美团知识产权声明》无日期，**而且我从未证实它就是大众点评条款所并入的那一份**（原文明说"详见《知识产权声明》"却不给地址）。
6. 穷游、豆瓣、飞猪 —— 旧，但结论方向（禁止第三人使用）不太可能反向放松，优先级低。

**唯一没有"过期"概念的是维基系（维基导游中文版、中文维基百科、CC BY-SA 4.0 法律文本）**：CC 许可明文"协议不可撤销"。但有个反直觉的点：**我引的那页是 wiki 页面，任何人随时能改**（`Wikivoyage:版权信息` 本身是条目）。所以我绑定的不是那个网址，是 2026-09-30 那份字节——这才是我存原始 HTML 的唯一理由。

### ② "中文 UGC 平台普遍不可用"还算数吗

**算数，而且比交文件那天更硬。** 交完之后我把条文又过了一遍，看到的是同一个结构，不是一串巧合：

- 能取到条款的 9 个平台里，**7 家把用户的永久/独家/可转授权写进条文**（美团那条甚至写明"独家且不可撤销"、"或向第三方自主进行任何必要的转授权"；携程是"无偿独家转让"；B站是"永久、非专属、可转让、可转授权"；去哪儿是"免费、永久、不可撤销、非独家…允许再授权"）。另 2 家用的是另一套（微信公众平台、飞猪法律声明）：**"未经许可第三人不得使用或创造相关衍生作品"**。两套写法，同一个结果。
- **唯一把"打印"写进条文的平台是去哪儿**，而它写的恰好是 `仅用于个人欣赏之目的，不得用于商业目的`。**连唯一提到打印的那家，都正好把我们的用途排除掉。**
- 所以不是"我们没找到口子"。**把第三人使用整块封死、并由平台收走转授权，这就是中文 UGC 平台的条款设计本身。**

还有一条和许可无关、但我上次没有说到位的东西：**评论是动态信息。** design-core §3 自己规定"动态信息永不被缓存为真值"。**哪怕明天给我一份永久许可，把"最近的 5 条评价"印进要带出国的攻略，也违反这条规则**——评论一周就旧了。A4 的原型形态在**许可**和**事实层纪律**两条上同时不成立。

**它的含义我说白：产品最想要的那类内容（中文用户的真实评价），恰好是中文平台条款锁得最死的一类内容。** 这不是运气差，是 UGC 平台十几年的商业模式。

### ③ 那"不因文化差异害怕"靠什么实现 —— 我的判断

**A4 不应按原型形态做。** 三条理由都在本项目自己的文本里，不需要外部假设：

1. **别人的评论进不了攻略的可信度阶梯。** §3 规定攻略每条带 `source_url` + `verified_at` + **一个由玩家行为派生的可信度标记**（亲自到过 ✅ / 读过来源 📖 / 只见过传闻 ⚠️）。第三方评价无论多真实，只能落在 ⚠️。**一本满是 ⚠️ 的打印攻略，是这个契约自己不允许的产物。**
2. **恐惧的解药不是别人的感想，是门前的确定性信息**：怎么进、要不要脱鞋、能不能拍照、最后入场几点、多少钱、怎么点单、被拒绝了怎么办。这些是**事实字段 + 一句文化解释**，属于我这条线的城市包（可执行性清单），可打印、可溯源、可复核，**不依赖任何 UGC 许可**。
3. **设计里已经有更合适的机制。** §4 的 `gloss`（信念图：你读懂了哪些招牌）与 `derived/read`（你亲自到过 / 你读过来源）说明：**"不因文化差异害怕"是被设计成"你读懂了招牌 + 你亲自确认过"，从来不是"别人告诉你"。** A4 的评论层在这套设计里没有承重位置。

**我见过的、许可干净的中文内容源，能替代"别人的真实评价"的，只有两类：**

- **维基导游中文版（CC BY-SA 4.0）** —— 中文；许可允许永久存储、打印、再分发（明文含"打印""复印""出售"），义务是署名 + 相同方式共享。它给的是"这里是什么、怎么去、要注意什么"的**叙述性指南**，形态是**条目，不是"最近 5 条评价"**。
  **但我必须自己认领一个空洞：我没有核实它对京都/大阪的实际覆盖和质量——我一次都没打开过它的京都条目。** 所以我不能说它能顶上。**这是一次抓取就能定的事，而我把它漏掉了。**
- **官方/运营方中文来源（观光局、寺院、铁道公司）** —— **我没有取得任何一份可用的再利用条款**（japan.travel 中文站我只抓了首页、未见版权条款），所以**我不能称它"许可干净"**。我能给的只是一条**路线判断**：这类主体与 UGC 平台有结构性差别——**他们有动机让中文旅客读懂，那是他们的 KPI**，所以"一封授权邮件"是有可能谈通的；而 UGC 平台的条款是整块封死并收归平台。**这是可能性，不是已核实的许可；核实之前不许进事实层。**

**结论（一句话）：砍掉"5 条真实评论"；保留"附近兴趣点"（名称/位置/类别可以从许可干净的源构建）；腾出的位置给"门前可执行性清单 + 一句文化解释"，来源用维基导游 CC BY-SA + 官方/运营方（后者须先拿到授权）。**

## 1. 我实际做了什么

- 用 `curl` / `Invoke-WebRequest` 打了约 40 个 URL（含 404 / 429 / 202 的失败），存原始字节、生成纯文本渲染，写了 `FETCH-MANIFEST.md`（URL → 文件 → HTTP 状态 → 备注）。
- **写了 `extract-text.mjs`，因为共享的 `html-to-text.mjs` 会静默删掉条款正文**：携程、大众点评等把可见条款放在 `<script type="text/lizard-template">` 或 Next.js `pageProps` JSON 里，一刀切剥 `<script>` 把携程 7,000 字的服务协议削成 **304 字**。用共享脚本，我会把 4 家平台记成"取不到"。
- 去取了 **CC BY-SA 4.0 的中文法律文本**，不只是 wiki 页——因为"打印这一媒介是否被覆盖""回链是否强制"是唯一判据，不能靠"CC 就是开放"的印象。结论是：媒介无限制，URI 只要求"在合理可行情况下"。
- 36/36 引文经 `verify-quotes.mjs` 对保存的字节逐字校验。
- **我认为自己最有价值的一条结论**：不是"中文平台不可用"（这条几乎必然），而是**13 行裁决里有 2 行的结论必须是"未取到"而不是"不可用"**。马蜂窝全站腾讯验证码、小红书 SPA 空壳——把它们按声誉写成"也不可用"，表格会更干净、更好看，也更假。

## 2. 做对的 / 做错的

**做对（只有三条）：**
1. 把"未取到"和"不可用"当成两种结论，而不是把未知填成否定。
2. 引文机械校验 + 保留原始字节，不要求别人信我。
3. 去拿许可原文而不是靠印象——这一步直接决定了"维基导游能不能印"这个答案。

**做错（四条，按严重度）：**
1. **携程那条用了 2017 年的旧页路径就当成了"服务协议"。** 我甚至在写文件时看到页内"§6 版权声明"就认为足够，收手了。**没有版本证据的条文不该直接进裁决表。**
2. **7 条来源在没有版本日期的情况下被我当正常引用写了出去。** 无日期的条款引用 = 引用一份不可定位的文件。
3. **优先级错，而且是我自己造成的。** 我花力气把覆盖从 8 家扩到 13 家（加了豆瓣、飞猪**商家**协议、japan.travel 首页），**却一次都没打开 zh.wikivoyage 的京都/大阪条目**。我把"取证广度"当成了目标；真正的目标是"中文玩家能不能读懂一个地点的真实情况"。**japan.travel 和飞猪商家协议是死重量。**
4. **顺序错。** 我先用共享脚本跑出一堆 300 字的"空壳"，**先怀疑站点、后怀疑工具**。正确顺序是：拿到"HTTP 200 + 文本极短"，先怀疑提取器。

## 3. 这个项目现在哪里不对（不客气版）

- **最不对的一条：一份"此路不通"的调研没有推翻任何裁定。** A4 先被裁定纳入范围，然后我这条线出了"中文 UGC 评论拿不到、拿不住"的结论，然后**没有任何设计变更**——A4 仍是"附近兴趣点 + 5 条评论"的原型形态，一行也没为它写过。**如果 recon 的结论不能回退一个范围裁定，recon 就是装饰。** 顺序本该是：先问"评论从哪来、能不能印"，再裁"要不要纳入"。
- **三线按语言/地区分，我认为分错了轴。** 决定 A4 生死的唯一尺子是"许可是否允许永久存储 + 离线打印再分发"——三线共用同一把尺。按地域分线，结果是每一线各自重造"能不能印"的判断；我在 C 线费力得出的 CC BY-SA 打印结论，A/B 线大概率也在各自重造。**我不确定 A/B 的实际内容**，这是从我自己任务卡推断的；若已按许可分好，这条不成立。
- **"不给建议"这条规则在只剩一条路的时候变成了伤害。** 我的卡明确写"不给'选哪个'的建议"，我遵守了，于是写到"可行路径只剩两条"就收手。**它防住了越权，也防住了我说出"这条路是死的"。** 建议改成：**不给"选哪个赢家"，但必须给"哪条路已死"。**
- **门在查形式，不查"有没有人用"。** `verify-quotes.mjs` 能查引文是否逐字，manifest 能查抓了什么；**没有一道门能查出"这份结论躺了三天没被引用"**。这个项目最贵的失败不是抄错引文，是**一份正确的结论躺在目录里**。如果只加一道门，我建议加这个：**每个 recon 文件必须在 design-core 里有落点，否则不许 complete。**

## 4. 重来一次

**先做**：先抓 zh.wikivoyage 的京都/大阪条目 + 一条官方中文来源，先判断"许可干净的中文内容能不能撑起一个地点的说明"；**再去**抓平台条款。顺序反了，我就是在给一条已经死掉的路做完美取证。
**不做**：不做平台数量的军备竞赛（13 家 vs 8 家对决策没有差别）；不引用没有版本日期的条款下结论；**不在确认"这份结论会被谁用"之前就 complete。**
