## ⑤ Mapillary 免费影像 —— **确认需要凭据，我不会去取**

**直接向 API 发请求（不是读文档，是实测）**：

```
无 token：
  {"error":{"message":"Invalid OAuth 2.0 Access Token","type":"MLYApiException","code":190}}
  HTTP 500

带一个格式正确的假 token（MLY|…|…）：
  {"error":{"message":"Service temporarily unavailable","code":2,"is_transient":true}}
  HTTP 500
```

**结论**：
- **API 是活的**（它区分"缺 token"与"坏 token"，返回不同的 `code`）
- **`graph.mapillary.com` 需要 OAuth 2.0 access token**——**这与我先前的断言一致**（只是当时我没试）
- **我不会去注册账户取 token**：那是**用我的身份为一个数据源开户**，而**项目的证据规范要求溯源可核**——**一个由 agent 私开账户取得的影像，下一个接手的人无法复核**

**所以这一条是"需要凭据，而我不取"，不是"取不到"。** 区别重要：**如果你有 Mapillary 账户并愿意提供，这条就通了。**

## 意外收获：两栋楼的**官方规格**（可入档）

来自 [オフィスナビ ダイヤビル](https://www.office-navi.jp/building/28000112/)（逐字）：

> `京都ダイヤビル 京都府京都市下京区四条通烏丸東入長刀鉾町10`
> `烏丸駅徒歩1分、四条駅徒歩1分`
> **`地上8階/地下1階`**（`新耐震基準（対応工事済み）/制震構造/2007年10月築`）
> `個別空調 24時間使用可能 OAフロア エレベーター 駐車場`

**`2007年10月築` 与 ODbL 里 OSM 的 `start_date: 2007-10` 一致**——**两个独立来源互相印证建物年代**。
**注意"地下1階"**：**南楼也有地下层**，与北楼一样有地下街进出——**而设计里南侧 5 扇全是街面门。**

**楼号**：京都ダイヤビル `28000112` · 京都三井ビルディング `28000116`（可作为后续查证的稳定键）
